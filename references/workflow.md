# 作業と状態遷移

## 実行順

1. `doctor` → `analyze`。元画像とnormalized.pngを目視。未対応フレームや色管理の失敗を解決する。
2. sidecarへ観測・仮説・保護対象・用途を記入する。未確定の隠れた形は `inferred_hidden`。
3. 画像別の候補を作成。独立したパーツの羅列ではなく共有境界と前後関係を設計する。フラットな隣接面なら `mosaic-draft` を初期候補にしてよい。
4. 再利用できる生成コードを作業フォルダに保存。SVGのidは意味に対応させる。
5. 構造SVGを書き出す。初期候補を `iterations/00/` に保持する。
6. `check`で最終バイト列を検査・描画。比較画像と問題領域を目視する。
7. 問題をG/T/S/R/Cへ分類して局所修正。最大3回、2回連続改善なしなら停止。
8. 最良の候補をresult.svgとし、最終バイト列に対してcheckを再実行。sidecarと納品名を整理する。

| 診断 | 見るもの | 修正候補 |
|---|---|---|
| G: 幾何 | 端点、共有edge、有限弧 | 共有変数、共同fit |
| T: 位相 | 穴、接続、未割当領域 | ラベル仮説・接続の修正 |
| S: 書き出し | 丸め、arc flag、transform | 同一数値の再利用、再parse |
| R: 被覆 | 内部alpha欠損・倍率差 | 合成・塗り構造の候補比較 |
| C: 色 | alpha正常でも残る筋 | 下地paint・順序・色空間 |

## 作業フォルダ

`input/`, `proposals/`, `iterations/00/`以降、`final/`を使う。ユーザーの既存成果物は別名保存。
改善の採否は同じ入力、同じ描画器、同じ表示条件で比較する。
チェック後にSVGを最適化・整形・再保存したら再検査する。

## 人による判断が必要な点

未知の背景除去、文字の復元、見えない形の創作など、観測で解けず目的が変わる場合は質問する。
既定の忠実変換を進められるなら余計な承認待ちを作らない。
ユーザーの依頼範囲を外部サービスへの送信や公開へ拡張しない。

## 写真の候補を改善する例

32/64/128色候補を原画像と並べる → 主体の輪郭・陰影の境目を抽出 → 少数の大きなパスを作る。
差が大きい領域で、輪郭を細分化するか、gradientを増やすか、別paintを加えるか選ぶ。
自動候補が背景・顔・細線を潰したらその候補を最終形にしない。適合度が足りなければpartialで返す。
専用自動エンジンや一意な逆変換の存在を前提にしない。
