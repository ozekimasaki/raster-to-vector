# Raster to Vector 統合理論・技術レビュー
## CFV-X：円フィッティングを核にした、観測整合・構造復元・検証可能性の統合設計

**版：1.0 — 理論レビュー／実装仕様の基礎**  
**調査基準日：2026-09-08**  
**対象：高精度で編集可能なSVGを生成するRaster-to-Vectorエンジン**

> 最優先するのは、入力に忠実であること。  
> 円・円弧・直線などの構造は、その忠実度を損なわない範囲で復元する。  
> そして「観測できたこと」「推定したこと」「保証できたこと」を混同しない。

本書は、これまで検討した **Circle-First Vectorization（CFV）** と **Inverse Rasterization** を技術的にレビューし、矛盾や過剰な保証を修正した統合設計である。仮称を **CFV-X** とする。名称は本書内の作業名であり、既存製品名・確立済み学術用語ではない。

「最高」は無条件の世界一を意味しない。本書では、**指定された入力範囲・許容誤差・計算予算に対して、精度と編集性を両立することを目指す設計**として具体化する。実製品としての優位性は、独立したベンチマークを経て初めて判断できる。

### 記述の区分

- **既知／仕様**：論文・標準仕様に基づく事項。本文の `[Sxx]` が末尾の一次資料に対応する。

## 1. 結論：完成形の設計原則

最も強い構成は、円だけを大量に配置する方法でも、AIにSVGを一括生成させる方法でもない。

**複数の幾何仮説を生成し、画像が生成された過程との整合性で絞り込み、独立した検証器で最終成果物を確認する方式**とする。

```text
入力画像・メタデータ
    ↓
入力条件／劣化／透明度の分析
    ↓
領域・ストローク・レイヤー・輪郭の候補
    ↓
円／円弧／直線／楕円／Bézierの候補
    ↓
離散構造の探索 ＋ 連続パラメータの最適化
    ↓
画像生成過程を使った逆ラスタライズ
    ↓
観測に裏づけられた幾何関係の復元
    ↓
独立した幾何検証・位相検証
    ↓
SVG書き出し → 再読み込み → 実レンダラー検証
    ↓
SVG ＋ 編集用構造 ＋ 品質レポート
```

重要な変更は次の六つである。

**第一に、Circle-firstは探索方針であり、忠実度より優先する制約ではない。** 円・円弧で説明できるときは円として出す。しかし、真に楕円や自由曲線である形を、多数の円弧へ無理に分解しない。

**第二に、輪郭点は観測そのものではなく、画像から作った推定値である。** 点群フィットは強い初期値生成器として残し、最終的には入力画素との整合性も確認する。

**第三に、最適化用の描画器と、品質確認用の描画器を分ける。** 最適化には微分の扱いやすさが必要であり、検証には幾何・積分・SVG実装との整合性が必要である。この二つを同一の近似器だけに任せない。[S05][S15]

**第四に、誤差保証には必ず比較対象を明記する。** 推定輪郭に対する最大誤差と、失われた元SVGに対する最大誤差は別である。

**第五に、円中心や半径の不確実性を出力する。** 残差が小さくても、短い円弧から半径が精密に決まるとは限らない。[S01][S03]

**第六に、成功だけでなく「未達」「判定不能」を正しく返す。** 検証できなかったものを、黙って成功扱いにしない。

## 2. これまでの理論のレビューと修正

これまでの方向性は有効である。ただし、以下はそのまま仕様にしてはいけない。

| これまでの主張・発想 | レビュー結果 | 統合版での扱い |
|---|---|---|
| 円を増やせば高精度になる | 条件付き。局所誤差は減らせても、編集性・接続・数値安定性は悪化し得る | 円以外のモデルとも比較する |
| 最大誤差εを満たせば元画像を保証できる | 比較対象が不明確 | 推定輪郭・観測画素・真の元形状を区別する |
| α=0.5が本来の輪郭になる | 特定の対称なエッジモデルでは有効。曲率・ぼけ・透明度で偏り得る | 初期候補として利用し、最終確定にはしない |
| 透過PNGのαは被覆率である | 常には成り立たない | 材質の透明度と幾何被覆率を分離する |
| すべてlinear RGBへ変換すれば正しい | 正しい合成を設計する話と、既存画像の生成過程を逆算する話が混在 | 色空間・合成順序も観測モデルに含める |
| Hyper → 幾何最小二乗なら必ず精度が上がる | 残差最小化とパラメータ推定誤差は別 | 複数推定器を比較し、観測モデルに合うものを採用 |
| HyperとHyperLSはほぼ同じ | 関連するが同一ではない | 論文・正規化・実装を区別する |
| 潜在角度を追加すると新たな精度が得られる | 自由角度・等方誤差なら通常の幾何フィットと等価 | 分布・順序・異方性など、追加情報があるときに採用 |
| 半円未満は特殊solver、30°未満は別solver | 一律の角度閾値には根拠が不足 | 情報量・条件数・曲率の信頼区間で判定 |
| 共有境界ならアンチエイリアスの継ぎ目が消える | 幾何の隙間は減るが、合成由来の継ぎ目は残り得る | 境界共有と描画の被覆相関を別々に扱う |
| PSFも同時推定すればよい | 形状・ぼけ・透明度の識別不能性が増える場合がある | 単純なモデルから選び、識別可能性を検査 |
| Exact Coverageなら描画も正確 | 単純図形・box filterなどの条件付き | 合成・フィルタ・数値積分の誤差も管理 |
| 拡大した画像を追加すれば情報が増える | 同一画像の補間は独立観測を増やさない | multi-scaleは最適化補助として扱う |
| 複数サイズのロゴは常に追加情報になる | 同じ元画像のリサイズや別デザインなら成立しない | 生成来歴と観測相関を確認する |
| 二分探索とprefix sumでO(N log N)になる | 一般の全工程には保証できない | 候補数・検証コスト・探索近似を分けて評価 |
| 通常のDPで接線や全体制約も最適化できる | 相互依存があると単純な加算DPでは不十分 | 接続状態を拡張し、全体制約は別工程で解く |
| 接線と曲率を一致させればよい | 角が消える。異なる半径の円弧にG2を強制するのも不適切 | 通常はG0、滑らかさの根拠があればG1 |
| 出力前の幾何が正しければSVGも正しい | 丸め・変換・SVGの半径補正で変化し得る | 書き出したバイト列から再検証 |
| 最近のAI vectorizerは精度が低いので使わない | 一括した断定はできない | 学習系も比較対象・候補生成器として評価 |
| 幾何関係の復元自体が新規性になる | 関連分野に多数の先行研究がある | 新規性は統合・保証・性能を含めて検証する |

円フィッティングのバイアス解析、HyperLS、円弧上のサンプリングモデルについては、それぞれ異なる前提の研究として読む必要がある。[S01][S02][S03] 透明度・合成・円弧出力の修正はSVG／PNGの仕様とも整合させる。[S16][S17][S18][S19]

**レビューの結論：円フィッティングを捨てるのではなく、その担当範囲を明確にする。**

## 3. 何を「精度」と呼ぶのか

少なくとも六つの軸を分ける。

| 軸 | 定義 | 主な検査 |
|---|---|---|
| 観測忠実度 | SVGを適切に描画した結果が入力画素に合うか | 色・α・エッジ帯域の差 |
| 幾何忠実度 | 曲線・領域の位置が基準形状に合うか | 双方向Hausdorff距離、面積差 |
| 位相忠実度 | 穴・接続・包含・交差関係が正しいか | 領域グラフ、交差判定 |
| 構造忠実度 | 円、同半径、ストローク等の構築意図が妥当か | 合成データの正解構造との比較 |
| 編集性 | 少ない自然な操作で意図した編集ができるか | ノード数、共有パラメータ、編集テスト |
| 移植性 | 別の描画器・倍率でも破綻しないか | 書き出し後の複数環境テスト |

### 3.1 画像差だけを最小にする落とし穴

各ピクセルを同色の長方形で置き換えれば、任意のラスター画像に一致するベクトル表現は作れる。しかし、それだけでは円・曲線・レイヤーを復元したことにならない。

逆に、非常に少ない図形で美しく再構成しても、細い線や文字の穴を消していたら高精度ではない。

したがってCFV-Xは、**精度を維持したうえで構造と編集性を評価する**。圧縮率だけ、円弧率だけ、画像類似度だけでは完成としない。

### 3.2 二つの製品モード

**忠実変換モード**は、入力の見た目を維持する。人工的なにじみや微妙な非対称性も、ユーザーが消すと指定しない限り勝手に直さない。

**構造復元モード**は、ラスタライズ・スキャン等の劣化を説明し、その手前の形状を推定する。出力が入力よりシャープになる場合、見た目の変更として明示する。

この二つの目的を、同じ「精度」というスライダーへ隠してはいけない。

### 3.3 単位

幾何誤差の基本単位は **入力画像の1ピクセル** とする。SVGのviewBox座標への変換係数を保存し、画面上のCSS pixelやデバイスpixelと混ぜない。

色差は別単位で扱う。例えば正規化RGBの差と幾何誤差0.1pxを、そのまま加算して意味のある品質値にすることはできない。

## 4. 復元可能性と、一意に決まらない部分

### 4.1 一枚のPNGから元SVGは一般には一意に決まらない

これは悲観ではなく、逆問題を正しく定義するための出発点である。

1ピクセル内の直線エッジ位置を $t\in[0,1]$、白い領域の被覆率を $1-t$ とする。8bitへの丸めが

$$
q(t)=\operatorname{round}(255(1-t))
$$

なら、$t=0.2501$ と $t=0.2502$ はどちらも同じ値191になる。

**異なる連続幾何が、同じ離散観測を生む。** この例は第19章のコードでも確認している。

同様に、完全に隠れた形状、透明な領域の色、複数の等価なパス分割は、見えている画素だけから確定できない。

### 4.2 目標は「観測等価な候補集合」の中から適切な構造を選ぶこと

観測モデル $m$、画像生成過程のパラメータ $\eta$、ベクトルシーン $V$ に対し、

$$
\mathcal{E}_{\tau}(I)
=
\left\{(V,\eta,m)\mid
D(R_{m,\eta}(V),I)\le \tau
\right\}
$$

を考える。

この集合の中で、入力に合い、編集しやすく、不必要な複雑さの少ない表現を選ぶ。集合が広い部分は、不確実性として残す。

### 4.3 subpixel推定と、subpixel保証は違う

多数の境界画素から円を推定すれば、1pxより細かい中心・半径を推定できる。しかし、

- 観測モデルが正しいか。
- サンプリング条件が十分か。
- 画像に圧縮や再サンプリングがあるか。
- パラメータが互いに代替可能でないか。

によって、真値に対する精度は変わる。

小数点以下の桁を多く出すことは、情報量を増やさない。

### 4.4 不確実性の分類

**観測不確実性**はノイズ・量子化・ぼけによる。

**モデル不確実性**は「円か楕円か」「半透明かAAか」などの説明候補による。

**構造不確実性**は、接続・レイヤー順・隠れた形状による。

**数値誤差**はsolver、積分、丸め、幾何判定による。

これらを一つのconfidence値で隠さず、可能な限り別々に報告する。

## 5. 統一問題設定と最適化の優先順位

### 5.1 変数

ベクトルシーンを

$$
V=(z,\theta)
$$

とする。

$z$ は離散構造であり、図形の種類・個数、領域の隣接、パス接続、レイヤー順、採用する幾何関係を含む。

$\theta$ は連続量であり、座標、半径、曲率、制御点、ストローク幅、色、透明度、グラデーション等を含む。

入力を説明する観測モデルを $m$、その連続パラメータを $\eta$ とする。

$$
I \sim p(I\mid V,m,\eta)
$$

既知のSVGを再ラスタライズして損失を最適化する考えは、微分可能ベクトル描画の研究に基盤がある。ただし、離散構造や保証まで自動的に解決されるわけではない。[S05][S07]

### 5.2 制約

製品の品質契約を $\mathcal{F}$ として、

$$
\mathcal{F}
=
\left\{
V:
\begin{array}{l}
V\text{ が有効な幾何・SVG構造である}\\
T(V)\text{ が承認済み位相仮説と整合する}\\
d_H(\partial V,B_{\rm ref})\le \epsilon_{\rm geom}
\quad\text{（基準輪郭がある場合）}\\
D_{\rm native}(V,I)\le \tau_{\rm native}
\quad\text{（忠実変換モード）}
\end{array}
\right\}
$$

と定義する。

ここで $B_{\rm ref}$ は明示された基準輪郭である。入力画像から推定した輪郭なら、その出自を記録する。真の元輪郭がないのに $B_{\rm ref}$ を「正解」と呼ばない。

### 5.3 精度優先の二段階選択

まず、品質契約の範囲で観測損失を改善する。

$$
L_{\rm obs}^{*}
=
\min_{V\in\mathcal{F},\,m,\eta}
L_{\rm obs}(V,m,\eta)
$$

次に、同等の忠実度を持つ候補集合

$$
\mathcal{F}_{\Delta}
=
\left\{
(V,m,\eta):
V\in\mathcal{F},
L_{\rm obs}\le L_{\rm obs}^{*}+\Delta_{\rm obs}
\right\}
$$

内で、記述複雑度・編集性・適切な幾何構造を比較する。

$$
\min_{\mathcal{F}_{\Delta}}
C_{\rm description}(V)
$$

**限界精度設定では $\Delta_{\rm obs}$ を数値許容誤差程度にする。** ノイズと区別できない差を許容する設定では、$\Delta_{\rm obs}$ を観測モデルに基づいて設定する。どちらもユーザーに明示し、円を増やす／減らすために勝手に広げない。

実装では大域最小値 $L_{\rm obs}^{*}$ が求まるとは限らない。その場合は **探索中の最良可行値** と明記し、大域最適性を主張しない。

### 5.4 複雑度に含めるもの

$$
C_{\rm description}
=
\lambda_1N_{\rm dof}
+\lambda_2N_{\rm segments}
+\lambda_3N_{\rm layers}
+\lambda_4N_{\rm special\ features}
+\lambda_5C_{\rm editing}
$$

図形数だけでなく自由度・レイヤー・特殊機能・操作の自然さを見る。

60個の円弧で表すより、1本の適切なBézierで表す方が忠実で編集しやすい場合は、Bézierを採用する。円弧率を上げること自体を目的関数にしない。

### 5.5 「ノイズまで一致」と「精度」を分離する

忠実変換ではノイズも含めた画素一致が目標になり得る。一方、構造復元ではノイズを形状化しない方が真の幾何へ近い場合がある。

したがって、観測ノイズの説明と図形の説明を分離する。モデルが誤っているのに、頂点を増やしてすべてを吸収する設計にはしない。

## 6. 入力画像ができるまでの観測モデル

### 6.1 基本モデル

線形光で連続合成し、フィルタと画素積分を行う理想化モデルなら、

$$
I_p =
Q\!\left[
T\!\left(
\frac{1}{|P_p|}
\int_{P_p}
(K_\eta * C_V)(x)\,dx
\right)
\right]+\text{観測誤差}
$$

と書ける。

- $C_V(x)$：位置 $x$ における連続的な合成結果。
- $K_\eta$：PSFや再サンプリングに対応するフィルタ。
- $P_p$：画素の面積。
- $T$：色空間の符号化・伝達関数。
- $Q$：量子化等。

これは**一つの候補モデル**である。実際の画像では合成・フィルタ・色変換の順序や近似が異なる可能性があるため、常にこの式を正解として固定しない。

### 6.2 初期対応する観測モデル

最初は以下の少数に絞る。

| モデル | 主対象 | 未知量を増やしすぎない工夫 |
|---|---|---|
| 被覆率型 | 純色のロゴ・アイコン | フィルタは固定 |
| 軽いぼけ型 | スキャン・縮小画像 | 画像全体で共有する少数のぼけパラメータ |
| 既知レンダラー型 | 生成元が判明している画像 | 既知の描画条件を優先 |
| 圧縮劣化型 | JPEG等 | まずノイズ相関・ブロック性を扱い、完全codec推定は後回し |
| 構造不明型 | AI生成画像・複雑なイラスト | 不一致を報告し、自由曲線や領域表現へ切り替え |

PNGであることは、元の描画器・ぼけ・元の色合成方法が判明したことを意味しない。

### 6.3 αの扱い

PNGのalphaは不透明度の線形な割合であり、RGBと同じgamma変換を適用するものではない。また、PNGの格納色と内部演算に使うpremultiplied colorは区別する。[S16]

単純化すれば、境界で観測されるalphaは

$$
\alpha_{\rm observed}
\approx
\alpha_{\rm material}\cdot\alpha_{\rm coverage}
$$

となる場合がある。したがって、透明な素材の $\alpha=0.5$ と、不透明な形状が画素の半分を覆った $\alpha=0.5$ は、同じ意味ではない。

透明画素のRGBをそのまま高い重みで損失に入れない。内部では色とalphaを適切に関連づけ、透明境界の黒い縁や色漏れを防ぐ。

### 6.4 ぼけ推定は自由度を制限する

未知PSFを図形ごとに自由にすると、形状の誤差をぼけで説明できてしまう。画像とぼけ核を同時推定する逆問題には、単純な最適化だけでは好ましくない解を選ぶ問題がある。[S25]

CFV-Xでは、まず単純な観測モデルを使い、残差に系統的な構造がある場合のみモデルを追加する。

**形状の自由度を増やすか、観測モデルを増やすかを比較すること**が重要である。

### 6.5 量子化は連続値の誤差と分ける

8bitの値 $q$ は、量子化前の値が一定区間に入っていたことを示す。

$$
l_q=\max\left(0,\frac{q-\frac12}{255}\right),\qquad
u_q=\min\left(1,\frac{q+\frac12}{255}\right)
$$

既知の丸めモデルなら、予測値がこの区間内にある限り観測値と矛盾しない。

Gaussianな量子化前ノイズを仮定する場合には、

$$
p(q\mid\mu,\sigma)
=
\Phi\!\left(\frac{u_q-\mu}{\sigma}\right)
-
\Phi\!\left(\frac{l_q-\mu}{\sigma}\right)
$$

を使える。ただし端のbinではクリッピング規則に応じた確率質量を扱う。

この区間尤度は、整数画素を無限精度の実数とみなすより正確な観測表現になる。反面、量子化区間内の解は一意にならない。これは仕様として許容する。

<a id="sec07"></a>
## 7. 幾何・境界・レイヤーの内部表現

### 7.1 三つのグラフを分ける

**Boundary Graph**は、見えている領域間の境界を表す。頂点は接続点・角・交点、辺は共有された曲線区間、面は可視領域である。

**Scene Graph**は、図形・ストローク・グループ・レイヤー・clip・maskを表す。重なった物体の説明はこちらで行う。

**Constraint Graph**は、同心・同半径・接線・対称・等間隔等の関係を表す。

これらを混ぜない。可視境界が二つに分かれていても、同じ隠れた円に由来する可能性がある。一方、色が同じでも異なるオブジェクトである可能性がある。

領域の隣接と境界をグラフで扱う考え、位相を意識した領域統合には先行研究がある。[S09][S10]

### 7.2 プリミティブ

基本集合は次とする。

```text
LineSegment
Circle
CircularArc
Ellipse
EllipticalArc
QuadraticBezier
CubicBezier
```

長方形・角丸長方形・正多角形等は、これらからなる**構造化された複合プリミティブ**として追加できる。

画面上の同じ形がcircle要素、円弧path、strokeなど複数の記法で表せる場合、見た目・編集性・互換性に基づくcanonical formを定める。元のSVG文字列そのものの復元は目標にしない。

### 7.3 ストロークを二重輪郭にしない

線画では、内側・外側の輪郭を独立してfitするより、

$$
\text{stroke}=(\text{centerline},\text{width},\text{cap},\text{join})
$$

として推定した方が適切な場合がある。

円環なら、同心円という説明に加え、円のstrokeという説明も比較する。stroke幅を変えて編集できる方が意図に合うことがある。

線端・線の接合・miter等はSVGの描画仕様に従う。可変幅strokeは通常の一定幅strokeと区別し、必要に応じて塗りつぶし輪郭へ変換する。[S20]

### 7.4 色の内部構造

均一な塗り、線形グラデーション、放射グラデーションを区別する。色変化をすべて多数の細い領域に分割すると、geometryを不必要に複雑化する。

ただし、特殊な内部色表現を導入する場合は、標準SVGへ忠実に書き出せるか別途確認する。任意の研究用表現がそのまま標準SVGの編集性を持つわけではない。[S21]

<a id="sec08"></a>
## 8. 輪郭抽出と不確実性

### 8.1 輪郭は初期化に使い、最終目的と取り違えない

輪郭抽出は不要になるのではない。最適化を良い解に導くための重要な初期段階として残す。

```text
元画像を保持
    ↓
色領域／alpha／線状構造を解析
    ↓
複数の閾値・スケールで境界候補
    ↓
局所エッジモデルでsubpixel位置を推定
    ↓
角・交点・細線・低信頼区間をマーク
```

元画素は破壊せず、平滑化画像は候補生成用とする。最終損失を平滑化済み画像だけに対して計算しない。

### 8.2 二色混合による被覆率推定

両側の色 $C_A,C_B$ が既知で、採用した合成空間で線形混合が妥当な場合、

$$
P\approx \alpha C_A+(1-\alpha)C_B
$$

から

$$
\widehat{\alpha}
=
\operatorname{clip}_{[0,1]}
\frac{(P-C_B)\cdot(C_A-C_B)}
{\|C_A-C_B\|^2}
$$

を得る。

ただし色差が小さい場合は分母が小さくなり、推定が不安定になる。グラデーション、複数レイヤー、半透明、圧縮、未知の合成空間でもこのモデルは崩れる。

したがって、適用条件と残差を検査する。α=0.5の等値線は候補であり、普遍的な正解輪郭ではない。subpixelエッジ位置が信号モデルに依存することは、エッジ・線状構造の位置推定研究でも重要である。[S26]

### 8.3 法線方向の不確実性

推定点を

$$
p_i\sim \mathcal{N}(\mu_i,\Sigma_i)
$$

として扱うことを検討する。

円フィットのradial residualは、一次近似では法線方向の誤差に対応する。

$$
\sigma_{n,i}^2
=
n_i^\top\Sigma_i n_i
$$

したがって、

$$
L_{\rm edge}
=
\sum_i
\rho\!\left(
\frac{d_i}{\sqrt{\sigma_{n,i}^2+\sigma_{\rm floor}^2}}
\right)
$$

を初期フィットに使える。

ただし、同じエッジから細かく再サンプリングした点は独立ではない。点数を増やしただけでconfidenceを上げない。

### 8.4 曲率は候補生成の補助

弧長再サンプリングと局所多項式近似から接線・曲率を推定する。曲率が一定なら円弧の有力な候補になるが、微分によるノイズ増幅があるため強い判定条件にはしない。

角や交点をまたぐ平滑化は避ける。曲率推定に使った平滑化が、細部を消していないか元画像へ戻って検証する。

## 9. 円・円弧フィッティングの中核

### 9.1 二段階ではなく「複数初期値＋適切な最終目的」

円中心 $c=(a,b)$、半径 $r>0$ に対し、

$$
d_i=\|p_i-c\|-r
$$

を使う。

初期候補はTaubin、Hyper、HyperLS等から生成する。ただし、これらはそれぞれの正規化・バイアス補正・ノイズ仮定が異なる。単に名前を連結して順番に実行すればよいわけではない。[S01][S02]

```text
正規化座標
    ├─ Taubin等の高速初期値
    ├─ Hyper / HyperLS系の初期値
    └─ 必要に応じて局所・頑健候補
          ↓
幾何フィット／制約付きfit
          ↓
有限円弧としての距離・端点・向きを評価
          ↓
元画素に対する精密化
```

### 9.2 残差最小と真値に近いことは別

最小二乗の目的値が下がっても、半径の推定誤差が必ず減るわけではない。ノイズの下でのバイアスと分散も関係する。[S01]

したがって、Hyper系の解を幾何最小二乗へ渡して改善した場合も、「目的関数を改善した」と「真の円に近づいた」を分けて評価する。

### 9.3 最大誤差制約を本当に扱う

最小二乗は平均的な誤差を小さくする目的であり、

$$
\max_i|d_i|\le\epsilon
$$

を自動的に満たさない。

候補の可否を決める際は、例えば

$$
\min_{c,r,t}t
\quad\text{s.t.}\quad
|d_i(c,r)|\le t
$$

というminimax問題を検討するか、最小二乗候補を独立に検証して修正する。

**最小二乗候補がεを超えたことは、「その区間にε以内の円が存在しない」ことの証明ではない。** 第19章に簡単な反例を示す。

局所solverが失敗した場合も、infeasibleではなくunknownとして区別する。

### 9.4 円全体と有限円弧の距離は違う

円周へのradial distanceだけでは、円弧の反対側の点も距離0になってしまう。

有限円弧 $\gamma$ への距離は、

$$
d(p,\gamma)
=
\min_{\phi\in[\phi_0,\phi_0+\Delta\phi]}
\left\|
p-c-r(\cos\phi,\sin\phi)
\right\|
$$

である。区間内に射影角がなければ端点距離を使う。角度のunwrap、方向、長い弧／短い弧、端点の順序を明示する。

候補はこの有限円弧に対して検証する。

### 9.5 短い円弧は曲率表現で扱う

大きな円の短い一部分を中心・半径で直接表すと、中心が遠方へ飛んで不安定になりやすい。

局所的には、始点 $p_0$、単位接線 $t_0$、単位法線 $n_0$、符号付き曲率 $\kappa$、弧長 $s$ で

$$
\gamma(s)
=
p_0+
t_0\frac{\sin(\kappa s)}{\kappa}
+
n_0\frac{1-\cos(\kappa s)}{\kappa}
$$

と表せる。

$\kappa\to0$ では、

$$
\gamma(s)\to p_0+s\,t_0
$$

となり、直線へ連続的に移行する。

計算には

$$
\frac{\sin(\kappa s)}{\kappa}
=s\,\operatorname{sinc}(\kappa s)
$$

$$
\frac{1-\cos(\kappa s)}{\kappa}
=
\frac{\kappa s^2}{2}
\operatorname{sinc}^2\!\left(\frac{\kappa s}{2}\right)
$$

を使い、$\operatorname{sinc}(x)=\sin x/x$ と定義する。小さい $x$ では級数評価等で桁落ちを防ぐ。

この表現を初期・局所最適化に使い、十分に識別できた段階でSVGの円弧表現へ変換する。

### 9.6 直線への置換は信頼度だけで決めない

低信頼の円弧を直線へ置換してよいのは、直線も誤差契約を満たす場合だけである。

半径 $r$、中心角 $\Delta\phi$ の短い弧と弦の最大距離は

$$
e_{\rm sagitta}
=
r\left(1-\cos\frac{|\Delta\phi|}{2}\right)
$$

であり、これを幾何検証の補助に使える。

「30°未満だから直線」という固定ルールにはしない。

### 9.7 潜在角度を追加するだけでは新しい推定器にならない

等方誤差で、角度 $\phi_i$ を自由に選べる場合、

$$
\min_{\phi_i}
\left\|
p_i-c-r(\cos\phi_i,\sin\phi_i)
\right\|^2
=
(\|p_i-c\|-r)^2
$$

である。つまり、潜在角度を追加しても通常の幾何円フィットと同じ問題になる。

改善が生まれるのは、角度に順序・可視区間・確率分布・異方誤差などの追加構造を与えたときである。von Mises分布を仮定する円のstructural modelは、その仮定込みで検討する。任意の画像輪郭に自動適用しない。[S03]

### 9.8 推定confidenceの計算

局所的な残差のJacobianを $J$、重み行列を $W$ とすると、

$$
F=J^\top WJ
$$

を情報量の近似に使える。正則な局所モデルでは $F^{-1}$ が共分散近似になるが、ランク落ちや強い非線形性がある場合はそのまま使えない。[S22]

短い円弧では、次を併記する。

```text
残差の小ささ
半径／曲率の推定区間
中心位置の推定区間
Jacobianの条件数・有効ランク
観測モデルを変えたときの変動
```

「残差0.01px、confidence 0.99」のような、根拠のない単一指標にはしない。

## 10. 区間分割とモデル選択

### 10.1 区間候補の生成

輪郭点列 $p_0,\ldots,p_{N-1}$ に対し、区間 $[i,j]$ ごとに有限プリミティブ候補を生成する。

候補生成では、角、曲率の符号変化、接線の不連続、領域接続点を利用する。ただし、推定が不確実な場所では複数候補を残す。

モデルの探索順は、実装上は次が合理的である。

```text
直線・円・円弧を低コストで確認
    ↓
楕円・楕円弧
    ↓
二次／三次Bézier
    ↓
必要なら局所分割
```

これは速度のための順序であり、「円が見つかったら他の忠実な説明を見ない」という意味ではない。

### 10.2 candidateの三状態

各候補には、推定器の収束状態とは別に可否を持たせる。

| 状態 | 意味 |
|---|---|
| `feasible` | 指定された検査範囲で誤差制約を満たす候補が得られた |
| `infeasible_certified` | 指定モデル・区間では制約を満たせないことを根拠付きで確認 |
| `unknown` | solver不収束、検証予算不足、初期値不足等で未判定 |

安い代数フィットが失敗しただけでは、原則として`unknown`である。精度優先設定では、良い候補を誤って捨てるfalse negativeを避ける。

### 10.3 接続を含むDP

候補 $q$ が点 $i$ から点 $j$ を説明するとする。候補単体のコストを $w(q)$、直前候補 $p$ との接続コストを $J(p,q)$ とする。

接線やモデル間の接続が関係する場合、

$$
F(q)
=
w(q)
+
\min_{p:\operatorname{end}(p)=\operatorname{start}(q)}
\left[F(p)+J(p,q)\right]
$$

と、**直前の候補自体を状態にする**。

点番号だけを状態とする通常のDPでは、直前の接線方向・モデル・共有端点の条件が失われる。

このDPが最適化するのは、固定された候補集合と加算可能な接続コストの範囲である。後工程の全体対称性や共有半径まで含んだ大域最適化ではない。

### 10.4 閉曲線

閉輪郭には恣意的な始点がある。始点で分割結果が変わる問題を避けるため、

- 意味のある角や接続点を切れ目にする。
- 複数の切れ目候補を試す。
- 周期性を明示した候補グラフを使う。

等を検討する。最後と最初の接続条件も必ず検査する。

### 10.5 候補数の削減と二分探索の条件

prefix momentsは、区間の代数的な要約を高速に取得するために有効である。ただし、頑健重み・有限円弧への距離・連続誤差検証・反復最適化まで定数時間になるわけではない。

また、区間を伸ばしたときの **特定solverが返す残差** は、一般には単調ではない。

同一モデル族に対する「可行解が存在するか」という厳密な判定は、制約集合が包含関係にあるなら単調性を使える。しかし、端点条件・モデル族・サンプル選別まで変化する実装では、その前提を確認する必要がある。

したがって、拡張探索と二分探索を採用する際は、

```text
厳密に単調な判定
保守的な下界による枝刈り
ヒューリスティック探索
```

のどれかを明示する。ヒューリスティックを完全探索と呼ばない。

### 10.6 適応的な自由度

一定数の制御点を最初に固定するより、画像の複雑さに応じてpathや制御点を配分する考えはAdaVec等にも見られる。[S08]

CFV-Xでは残差を分析し、局所的に次を選ぶ。

```text
現在のモデルをさらに最適化
円から楕円へ変更
円弧からBézierへ変更
区間を分割
隣接区間を統合
色／グラデーションのモデルを変更
観測モデルを再検討
```

**誤差が大きいから必ず分割する、とはしない。** ぼけや色のモデルが間違っているなら、頂点を増やしても本質的には解決しない。

## 11. 幾何関係の復元と共同最適化

### 11.1 関係は仮説として追加する

同心・同半径・接線・対称性は、精度と編集性を高める有力な構造である。ただし、微妙な非対称性が意図されたデザインである可能性もある。

採用候補は次とする。

| 関係 | 制約の例 |
|---|---|
| 同じ円 | $c_1=c_2,\ r_1=r_2$ |
| 同心 | $c_1=c_2$ |
| 同半径 | $r_1=r_2$ |
| 円の外接 | $\|c_1-c_2\|=r_1+r_2$ |
| 円の内接 | $\|c_1-c_2\|=\lvert r_1-r_2\rvert$ |
| 直線と円の接触 | 中心から直線への距離が半径と一致 |
| 鏡映対称 | 対応点・接線・領域が同一の鏡映変換で対応 |
| 回転対称 | 共通中心と共通回転角による対応 |
| 等間隔・整列 | 共有方向や共有間隔による制約 |

### 11.2 近い値を丸めるのではなく、モデルを比較する

半径が49.93と50.07だから、直ちに50へ統一しない。

$$
H_0:\text{独立した半径}
$$

$$
H_1:\text{共有半径}
$$

の両方を画像全体へfitし、観測整合性・幾何誤差・不確実性・編集性を比較する。

パラメータ間距離には、単なる座標差より共分散を考慮する。ただし候補同士が同じ画素を利用している場合、独立性を仮定して共分散を単純加算しない。

### 11.3 共有パラメータによる改善の条件

同じ半径の円を複数同時にfitすれば、独立した観測が増えることで半径推定が安定する可能性がある。

ただし、共有半径仮説が正しく、観測が十分独立であることが条件である。未知PSFによる共通バイアスがある場合、円を増やしてもそのバイアスは消えない。

「円が4個だから必ず精度が4倍」などとは言わない。

### 11.4 G0・G1・G2を区別する

**G0**は位置がつながること。

**G1**は接線の方向が一致すること。曲線の進行方向まで合わせる。

**G2**は接線に加え、適切な向きで曲率が一致すること。

パラメータ微分の一致を要求するC1／C2とは区別する。SVGの見た目の滑らかさでは、通常は幾何学的連続性の方が直接的である。

異なる半径の円弧同士へG2を強制すると、曲率が一定であることから自由度が強く制限される。滑らかな円弧列には、まずG1を検討する。角には接線連続性を強制しない。共分散を用いたG1円弧スプライン近似にも先行研究がある。[S04]

### 11.5 Joint Optimization

採用した構造仮説の下で、

$$
\min_{\theta,\eta}
L_{\rm obs}(\theta,\eta)
$$

subject to

$$
C_{\rm exact}(\theta)=0,\qquad
g_{\rm safety}(\theta)\le0
$$

を解く。

共有中心・共有半径は、可能なら同一パラメータへの参照として表現し、巨大なpenaltyで「ほぼ等しい」を強制しない。

非線形の誤差制約や非交差制約には、対応する制約付きsolver、パラメータ化、あるいは検証付き更新を使う。通常の最小二乗solverへ高い重みを入れただけではhard constraintの保証にはならない。

### 11.6 観測モデルの未知量を含めた情報量

幾何 $\theta$ と観測条件 $\eta$ の情報行列を

$$
F=
\begin{pmatrix}
F_{\theta\theta}&F_{\theta\eta}\\
F_{\eta\theta}&F_{\eta\eta}
\end{pmatrix}
$$

とすると、正則な局所モデルの下で、未知の観測条件を考慮した幾何の有効情報は

$$
F_{\theta\mid\eta}
=
F_{\theta\theta}
-
F_{\theta\eta}F_{\eta\eta}^{-1}F_{\eta\theta}
$$

で評価できる。

これは「ぼけも推定したら幾何のconfidenceが必ず上がるわけではない」ことを示す。ランク落ち時は単純逆行列を使わず、識別不能な方向を明示する。共分散評価の一般的な注意点はCeresの公式資料にも整理されている。[S22]

### 11.7 隠れた円の復元

離れた円弧が同じ円を支持していても、隠れた部分まで観測で確認できたわけではない。

内部モデルには、

```text
observed_geometry
inferred_hidden_geometry
```

を分けて保存する。

隠れた形状を含む編集可能なレイヤー復元は有力な方向であり、amodal vectorizationの研究もある。[S14] ただし、生成補完した部分を「入力から保証された形状」と扱わない。

## 12. 逆ラスタライズと画素空間の精密化

### 12.1 三種類の描画器

CFV-Xでは描画を三層に分ける。

| 描画器 | 役割 | 要求 |
|---|---|---|
| Optimization Renderer | パラメータを効率よく更新 | 安定した勾配、段階的な高精度化 |
| Reference Renderer | 採用候補の数値検証 | 精度管理された積分・幾何評価 |
| Target SVG Renderer | 実際の出力確認 | ユーザーの利用環境に近い描画 |

同一の近似描画器で最適化と採点を完結させると、その近似器に特有の誤差へ最適化される可能性がある。

diffvgには異なる近似・サンプリング方式があり、描画の近似によるアーティファクトが論じられている。[S05] さらに、幾何の順方向近似精度と勾配の安定性のトレードオフを扱う新しい研究もある。[S15]

### 12.2 Exact Coverageの適用範囲

不透明な円領域 $C$、画素領域 $P_p$、box filterなら、

$$
\alpha_p
=
\frac{\operatorname{Area}(C\cap P_p)}
{\operatorname{Area}(P_p)}
$$

と定義できる。

円と四角形の交差面積は、円弧・線分を扱う解析的な分解や一次元積分で計算できる。第19章の検算では、境界画素だけに対する適応的一次元数値積分を用いた。

ただし、次は別問題である。

- 任意の重なり順・半透明・clip・maskを含むシーン。
- box filter以外のフィルタ。
- 任意のグラデーションや内部色。
- 数値積分の誤差を厳密に上から抑えること。
- ブラウザ等の実装との一致。

したがって、一般シーンで「exact」を名乗るには、何に対して正確なのかを限定する。通常のquadratureが小さい誤差推定値を返しても、それだけで厳密な区間保証にはならない。

#### 12.2.1 円と画素の交差面積を実装する式

円中心を $(c_x,c_y)$、半径を $r$、画素を
$[x_0,x_1]\times[y_0,y_1]$ とする。

$$
a=\max(x_0,c_x-r),\qquad b=\min(x_1,c_x+r)
$$

$$
s(x)=\sqrt{\max(0,r^2-(x-c_x)^2)}
$$

$$
h(x)=
\max\left(
0,\,
\min(y_1,c_y+s(x))-\max(y_0,c_y-s(x))
\right)
$$

なら、

$$
\alpha
=
\frac{1}{(x_1-x_0)(y_1-y_0)}
\int_a^b h(x)\,dx
$$

である。$a\ge b$ なら交差面積は0になる。

円と画素の上下辺が交差するx座標で区間を分ければ、被積分関数の切り替わりを明示して積分できる。円弧部分の原始関数には、

$$
\int\sqrt{r^2-u^2}\,du
=
\frac12\left[
u\sqrt{r^2-u^2}
+r^2\arcsin(u/r)
\right]
$$

が使える。

解析式であっても、接線付近・極小区間・差分の桁落ちを扱う必要がある。高精度検証用には区間評価や安定化した代替式を用意する。

#### 12.2.2 円の被覆率に対する解析的な勾配

円周のうち画素内部にある部分を $\Gamma$、外向き単位法線を $n$、画素面積を $A_p$ とする。

境界移動による面積変化から、通常の微分が成立する配置では、

$$
\frac{\partial\alpha}{\partial c_x}
=
\frac{1}{A_p}\int_\Gamma n_x\,ds
$$

$$
\frac{\partial\alpha}{\partial c_y}
=
\frac{1}{A_p}\int_\Gamma n_y\,ds
$$

$$
\frac{\partial\alpha}{\partial r}
=
\frac{1}{A_p}\int_\Gamma 1\,ds
$$

と導出できる。これは境界を通じて描画の微分を扱う考えと整合する。[S05]

画素内に入る角度区間が $[a_k,b_k]$ と求まっているなら、

$$
\frac{\partial\alpha}{\partial c_x}
=
\frac{r}{A_p}\sum_k(\sin b_k-\sin a_k)
$$

$$
\frac{\partial\alpha}{\partial c_y}
=
\frac{r}{A_p}\sum_k(\cos a_k-\cos b_k)
$$

$$
\frac{\partial\alpha}{\partial r}
=
\frac{r}{A_p}\sum_k(b_k-a_k)
$$

となる。

これにより、単一の塗りつぶし円に関しては、被覆率を毎回有限差分するだけでなく、境界区間から直接勾配を求める設計が可能になる。

ただし、画素の角への接触などの退化配置、半透明の合成、有限円弧からなる複合領域、blurを含む画像では、そのまま一般化しない。半径や中心が複数の境界へ共有されている場合は、関係する全境界の寄与を合算する。

**実装時には、解析勾配と独立な有限差分・数値積分を比較する単体テストを必須とする。** 本レビューの第19章の試験は有限差分を使っており、ここで提案した解析勾配版の実装試験ではない。

### 12.3 SDFは有用だが、円弧全体の描画モデルではない

円の符号付き距離は

$$
d(x)=\|x-c\|-r
$$

である。しかし、有限円弧には端点があり、strokeには幅と線端があり、塗りつぶしには閉じた領域とfill-ruleがある。

円のSDF一本で、一般の円弧pathや複雑な塗りを正しく描画できると仮定しない。

### 12.4 Optimization Rendererの設計

初期段階では、平滑な被覆近似や誤差を管理した曲線近似で勾配を安定化する。後半で、

```text
平滑化幅を縮小
積分・サンプリング精度を上げる
境界と接合部の評価密度を上げる
独立描画器で候補を再評価
```

する。

高い解像度へ補間した画像を新たな観測として追加するのではなく、**同じ観測の目的関数へ到達するためのcontinuation**として位置づける。

### 12.5 損失の構成

最終的な観測評価の中心は、

$$
L_{\rm obs}
=
-\log p(I\mid V,m,\eta)
$$

である。

補助的に、次を利用できる。

$$
L_{\rm aux}
=
\lambda_eL_{\rm edge}
+\lambda_gL_{\rm geometric\ prior}
+\lambda_tL_{\rm tangent}
$$

ただし、エッジも画素も同じ入力から得ている。両方を独立した測定として数え、情報量や信頼区間を過大評価しない。補助損失は初期化・正則化の役割として区別する。

### 12.6 色と形状を交互に最適化する

形が違うのに色を変えて画像差を小さくする、または色が違うのに境界を動かす、といった代替を抑えるため、

```text
幾何を固定して色・alphaを更新
色を固定して幾何を更新
共有境界・接続を検査
少量の共同更新
```

を繰り返す。

均一塗りでは、幾何を固定した色の推定が比較的単純になる場合がある。グラデーションを追加する場合は、自由度の増加が必要かを残差で確認する。

### 12.7 複数画像の利用

異なるサブピクセル位相・独立した描画・独立した観測条件を持つ複数画像があるなら、

$$
L_{\rm multi}
=
-\log p(I_1,\ldots,I_M\mid V,\eta_1,\ldots,\eta_M)
$$

で共同推定できる。

各観測が条件付き独立なら和へ分解できるが、同じPNGのリサイズ画像群なら独立ではない。独立性がない場合に損失を単純加算すると、同じ情報を何度も数えてしまう。

また、小サイズ用ロゴが形状調整された別デザインである可能性もある。幾何共有仮説を検査してから融合する。

### 12.8 JPEG等の扱い

最初からJPEG encoderを丸ごと微分可能にすることは必須ではない。順序として、

```text
圧縮による境界・色の不確実性を増やす
    ↓
相関のある残差モデルを使う
    ↓
必要なら量子化係数等の情報を使う
    ↓
効果が確認された範囲だけcodec-aware化する
```

とする。

量子化や丸めは不連続であり、forwardを模倣しただけでは有効な勾配は得られない。近似勾配・離散探索・区間尤度を使う場合も、最終的な観測整合性は別に検査する。

### 12.9 AI／学習器の位置づけ

学習器は、図形・レイヤー・対称性・隠れた構造の候補生成に使える。必要なら複数候補を生成して数値検証で選ぶ。

ただし、意味的に自然な絵へ修正することと、入力に忠実にすることは別である。生成的な補完は構造復元モードで明示的に扱う。

2026年のVectorArkは、実入力の劣化や幾何表現を考慮した学習型vectorizationを提案している。[S13] したがって「AI方式は精度が低い」と一括りにはせず、入力範囲をそろえて比較する。

## 13. 位相・共有境界・描画の継ぎ目

### 13.1 位相を保持するとは何か

少なくとも以下を確認する。

```text
連結成分
穴
領域の隣接
境界の接続次数
包含関係
交差・接触
レイヤーの前後関係
```

Euler特性が同じでも、隣接や接続の仕方が同じとは限らない。成分数と穴数だけの検査では不十分である。

入力自体が曖昧な場合は、複数の位相仮説を持つ。1px程度の線が接しているのか隙間があるのかを、根拠なく固定しない。

### 13.2 Hausdorff距離だけでは位相を保証できない

曲線が位置的に近くても、非常に小さい輪を追加したり、細い隙間をつぶしたりできる。

したがって、

$$
d_H(\partial V,B_{\rm ref})\le\epsilon
$$

だけを位相保証の代わりにしない。

局所の隙間幅 $g$ が小さい場所では、幾何の許容誤差を $g$ より十分小さく制限する方針を取れる。ただし、これも対応関係・交差検査・接続グラフと組み合わせる。

### 13.3 幾何境界の共有

二つの領域が同じ境界を持つ場合、一本の曲線を共有して両側から逆向きに参照する。これにより、別々のfitによる幾何の隙間を抑える。

交点や接点の数値判定は、ほぼ接するケースで壊れやすい。向き・incircle等に頑健な述語を用いる技法、円弧を含むarrangementの考え方を参考にする。[S23][S24]

ただし、直線向けの正確なorientation判定があるだけで、任意のBézier交差や三角関数を含む円弧演算まで自動的に保証されるわけではない。

### 13.4 共有境界でも描画の継ぎ目は生じ得る

一つの画素を、左右の不透明な領域がそれぞれ50%ずつ覆う場合を考える。

両者を別々に平均化したalphaでsource-overすると、

$$
\alpha_{\rm out}
=
0.5+0.5(1-0.5)=0.75
$$

となる。

一方、実際の左右の領域が画素全体を隙間なく埋めているなら、正しい総被覆率は1である。

これは、**画素内でどの位置を覆うかという相関情報を、個別の平均alphaにすると失う**ことを示す反例である。source-overの式自体は仕様通りでも、画素内の境界共有を表現できていない。[S17]

### 13.5 継ぎ目への対策

内部の参照描画では、可能な範囲で**サブピクセル位置ごとに領域／レイヤーを合成してから画素積分する**。

SVG出力では、実レンダラーの挙動を確認しながら次を使い分ける。

- 同色の接続領域は、見た目・編集意図を確認したうえで結合する。
- 不透明な重なり表現が適切な画像では、隠れる側を覆わせる表現を比較する。
- clipやmaskは、追加のAAや互換性も含めて検証する。
- 透明な領域へ、継ぎ目対策のためだけに無条件のoverlapを入れない。

重ね塗りによる修正は、半透明では色・alphaを変える。全入力へ適用する万能対策にはしない。

## 14. 連続誤差の検証と保証の範囲

### 14.1 四つの品質表現

| 表現 | 実際に言えること |
|---|---|
| 観測再現の測定値 | 指定描画器・倍率での画素差 |
| 基準輪郭への幾何保証 | 明示した連続基準曲線に対する距離上界 |
| モデル条件付き推定区間 | 仮定した観測モデルでの中心・半径等の不確実性 |
| 元形状への保証 | 真の基準形状、または基準推定の保証がある場合のみ |

製品画面で単に「最大誤差0.1px」と表示せず、何に対する0.1pxかを併記する。

### 14.2 双方向距離

二つの曲線集合 $A,B$ に対し、

$$
h(A,B)=\sup_{a\in A}\inf_{b\in B}\|a-b\|
$$

$$
d_H(A,B)=\max(h(A,B),h(B,A))
$$

を使う。

入力輪郭からSVGへの距離だけでは、SVG側に余計な突起やループがあることを見落とす。必ず逆方向も見る。

また、全曲線を一括して比較すると近くの別境界へ誤対応する場合がある。領域ラベル・対応区間・包含関係も利用する。

### 14.3 サンプル値から連続上界を作る

距離関数 $d(x,B)$ は1-Lipschitzである。

$$
|d(x,B)-d(y,B)|\le\|x-y\|
$$

したがって、曲線区間上の代表点 $x_0$ から、その区間内の任意点までの距離上界を $\delta$ とすると、

$$
d(x,B)\le d(x_0,B)+\delta
$$

を得る。

弧長で区間を管理し、代表点からの最大弧長が $\ell/2$ なら $\delta\le\ell/2$ と置ける。より鋭いbounding box、凸包、円弧の幾何境界を使ってもよい。

ただし $d(x_0,B)$ 自体も数値計算である。検証器では、その距離の上下界を管理する。

### 14.4 Branch-and-Bound検証

```text
各曲線区間について
    距離の下界 L と上界 U を作る

U <= epsilon:
    その区間は合格

L > epsilon:
    不合格

それ以外:
    区間を分割して再評価

時間／分割予算を超えた:
    判定不能
```

これを双方向に行う。

普通の倍精度計算と多数のサンプルだけで、数学的な「保証」を名乗らない。厳密保証を出す経路には、外向き丸めの区間演算、検証可能な幾何上界、退化処理等が必要である。

### 14.5 サンプル集合を使う保守的な代替

$S_A,S_B$ がそれぞれ曲線 $A,B$ のサンプル集合で、

$$
d_H(A,S_A)\le\delta_A,\qquad
d_H(B,S_B)\le\delta_B
$$

を別途保証できれば、三角不等式から

$$
d_H(A,B)
\le
\delta_A+d_H(S_A,S_B)+\delta_B
$$

を得る。

点群同士の距離計算にも数値誤差上界を加えれば、保守的な初期validatorを構築できる。

ただし、サンプル点数を指定するだけでは $\delta_A,\delta_B$ の保証にはならない。曲線の長さ・導関数・凸包等から上界を求める。

### 14.6 誤差予算

同じ幾何距離で結べる工程については、

$$
\epsilon_{\rm total}
\le
\epsilon_{\rm reference}
+\epsilon_{\rm fitting}
+\epsilon_{\rm conversion}
+\epsilon_{\rm serialization}
$$

という上界を設計できる。

- $\epsilon_{\rm reference}$：真の元形状から基準輪郭まで。
- $\epsilon_{\rm fitting}$：基準輪郭から内部幾何まで。
- $\epsilon_{\rm conversion}$：内部プリミティブから出力表現まで。
- $\epsilon_{\rm serialization}$：丸め・再解釈等の差。

**最初の項が未知なら、合計を元形状への保証として報告しない。**

また、この式に色差やPSNRを足してはいけない。工程間の距離・対象・単位を一致させる。

### 14.7 更新の採否

最適化で画像差が下がっても、位相や誤差上界が壊れたら採用しない。

```text
候補更新を別コピーに適用
    ↓
安価な検査
    ↓
必要な精密検査
    ↓
合格ならcommit
不合格ならrollback
未判定なら保留
```

この検証付き更新が、幾何関係のsnap、曲線の統合、SVGの軽量化にも共通する安全機構になる。

<a id="sec15"></a>
## 15. SVGへの書き出しと互換性

### 15.1 内部表現と出力表現を分離する

内部最適化は中心・半径・符号付き曲率・共有パラメータで行う。SVGは最終成果物の表現として扱う。

完全な独立円は`<circle>`、楕円は`<ellipse>`、有限直線は用途に応じて`<line>`またはpath、円弧はpathの`A`を使う。

ただし、円が他の曲線と同じ閉じた塗りを構成する場合は、その塗りを正しく表すpathが必要である。すべての円弧を独立した`<circle>`へ置き換えない。

### 15.2 円弧の変換

内部の中心表現から端点を計算し、

```svg
A r r 0 large-arc-flag sweep-flag x y
```

へ変換する。

SVGでは、端点・半径・flagから円弧が決まる。半径が端点間距離に対して小さすぎると、仕様上の補正が行われる。[S18][S19]

丸めによってこの補正が新たに発生していないか、再読み込み時に確認する。

### 15.3 完全な円を同一始終点のA一つで出さない

SVGの円弧では、終点が現在点と同一なら、その円弧は省略される扱いになる。[S18]

完全な円は`<circle>`、または少なくとも二つの円弧で表す。穴や複合pathの一部なら、fill-ruleと向きも含めて検査する。

### 15.4 向き・座標系・反転

SVGの通常の座標系と、内部計算の座標系を明示する。y軸反転や負のscaleがある場合、円弧の向き・回転・fill-ruleの解釈へ影響する。

変換を焼き込む場合も、円が非一様scaleで楕円になることを正しく扱う。円として保持したいからといって非一様変換を無視しない。

### 15.5 丸め精度は適応的にする

小数点以下を一律3桁にする、などのルールではなく、書き出し前後の幾何差を評価する。

```text
精度の高い値で書き出す
    ↓
丸め候補を試す
    ↓
再parseして幾何を復元
    ↓
連続誤差・位相・見た目を検証
    ↓
許容範囲の丸めだけ採用
```

同じ共有端点は、同一の数値表現を再利用する。

### 15.6 円弧からBézierへの変換

編集先が円弧を内部的にBézierへ変換する場合、円弧を保持したSVGと、互換性用のBézier版を別に評価する。

円や円弧の有理表現と、通常の多項式Bézier近似は同一ではない。変換するなら追加誤差を予算へ計上する。固定の円近似係数を「厳密な円」と扱わない。

### 15.7 二種類の出力を持つ

**標準SVG**は一般的な描画・交換用とする。

**編集用sidecar**には、同心・同半径等の制約、観測由来／推定由来の区別、信頼区間、元座標系を保存する。

標準SVGへ座標を書き出しただけでは、編集先が共有半径などの設計意図を保持するとは限らない。構造を維持した編集性は、sidecarを理解するエディタ側の機能でもある。

### 15.8 strict vector出力

strictモードでは、埋め込みラスターを使用しない。画像を`<image>`で内包しただけのSVGを「ベクトル化に成功」と報告しない。

フィルタ・mask・clip等は許可リストと互換性プロファイルで管理する。出力後に外部参照・スクリプト・埋め込みデータを検査する。

### 16.1 処理順

```text

    analyze_color_alpha_resolution_and_degradation(input)

    observation_hypotheses = propose_observation_models(input)
    structure_hypotheses = propose_regions_strokes_layers(input)
```

<a id="sec17"></a>
## 17. 計算量・安定性・実装構成

### 17.1 全体をO(N log N)と呼ばない

画素数を $P$、輪郭点数を $N$、候補数を $K$、接続候補数を $E$、反復数を $I$ とする。

| 工程 | 計算量を支配するもの |
|---|---|
| 画像前処理 | 画素数P、フィルタや領域処理 |
| 区間候補生成 | 最大O(N²)の区間とモデル数 |
| 候補の精密fit | 候補内の点数、反復数 |
| 候補グラフDP | 候補数Kと接続数E |
| 全体幾何制約 | 共有パラメータ、疎行列構造 |
| 逆ラスタライズ | 可視プリミティブ数、画素数、サンプル数、反復数 |
| 連続誤差検証 | 許容誤差、近接・退化配置、分割数 |
| SVG互換性検証 | 対象renderer数、倍率、出力規模 |

高速化後も、病的な入力や極端に小さい許容誤差に対して一律の実行時間を保証しない。

### 17.2 数値精度

幾何コアは原則としてf64を使う。局所座標の正規化、QR／SVD等の安定した線形代数、必要な箇所の補償和を検討する。

高次momentのprefix sumは、大きな値の差分による桁落ちを起こし得る。局所座標、ブロック単位の集計、安定性判定、再計算へのfallbackを用意する。

GPUの近似演算と、保証器の演算経路は分離する。厳密な位相・距離保証を任意の高速math設定へ任せない。

### 17.3 誤差に応じた計算配分

画像全体を均一に重く処理しない。

```text
均一領域:
    色・alphaの簡単な評価

境界:
    高精度な被覆率・幾何評価

角・交点・細線:
    位相と局所誤差へ計算を集中

低信頼円弧:
    複数仮説とパラメータ不確実性を評価
```

隠れたプリミティブや影響のない画素への計算を減らす。ただし、可視性の誤判定で必要な図形を捨てないよう検証する。

### 17.4 推奨アーキテクチャ

Rust等のネイティブコアを想定するが、言語そのものは理論の要件ではない。

```text
Core
├── image_and_metadata
├── observation_models
├── region_and_stroke_proposals
├── boundary_graph
├── primitive_fit
├── candidate_search
├── constraint_graph
├── inverse_render_optimization
├── geometry_validator
├── svg_serializer
└── report_and_provenance

Interfaces
├── CLI / batch
├── native API
├── WebAssembly preview
└── editor integration
```

高精度の最適化と検証はnative側、軽量previewはWASM側という分離が可能である。WASM previewと本処理が別の精度条件なら、その差を明示する。

### 17.5 再現性

保存する情報は、入力hash、設定、観測モデル、seed、solverの停止理由、依存ライブラリ版、renderer版、出力hash、検証結果である。

ユーザーが「昨日と半径が違う」と指摘した場合、候補生成の乱数・solver差・ライブラリ更新・入力変化を切り分けられる設計にする。

## 18. ベンチマークと品質判定

### 18.1 三種類のデータを分離する

**合成正解データ**では、元SVG・中心・半径・レイヤー・接続が分かる。幾何復元の精度を直接測れる。

**実入力データ**では、画像忠実度・編集性・互換性を評価する。元の幾何が分からない場合、真値への誤差は報告しない。

**困難例データ**では、成功率だけでなく適切な棄却・不確実性報告を評価する。

同じ元SVGの色違い・回転違い・解像度違いを、学習用と評価用へ無作為に分けるだけでは構造の漏洩が起こり得る。元デザイン単位で分離する。

### 18.2 合成データの項目

| 群 | 含める内容 |
|---|---|
| 単純形状 | 円、楕円、直線、角丸形状 |
| 円弧の識別 | 1°、5°、15°、30°、90°、180°、全円 |
| 近直線 | 大きい半径の短い円弧、弱い楕円曲率 |
| 接続 | G0、G1、角、T字、接触、交差 |
| 位相 | 穴、細い隙間、細線、多重包含 |
| 幾何関係 | 同心、同半径、対称、意図的に少し非対称 |
| stroke | 線端、join、円環、二重線 |
| 色 | 低コントラスト、グラデーション、透明度 |
| 劣化 | blur、縮小、量子化、圧縮、再ラスタライズ |
| 観測差 | 複数renderer、色空間、サブピクセル位相 |
| 隠蔽 | 部分円弧、複数レイヤー、隠れた形状 |
| 制約外 | 写真、強いテクスチャ、モデル不一致 |

### 18.3 inverse crimeを避ける

生成器と復元器が同じ近似モデルなら、実世界より簡単な問題になる。

開発中の単体試験では同じモデルを使ってよい。しかし、最終比較では、

```text
生成に使っていないrenderer
未知の縮小条件
未知の色処理
実際に劣化した画像
```

を含める。

同じ内部描画器だけで「世界最高の画素一致」を主張しない。

### 18.4 指標

| 分類 | 指標 |
|---|---|
| 幾何 | 双方向Hausdorff上界、平均／P95境界距離 |
| 領域 | IoU、面積差、境界対応の正しさ |
| 位相 | 隣接・穴・接続・包含の誤り |
| 円復元 | 中心・半径・曲率・円弧区間の誤差 |
| 観測 | RGB・alpha差、境界帯域差、対象renderer別の差 |
| 複雑さ | 自由度、path数、制御点数、ファイル容量 |
| 編集性 | 半径変更・色変更・移動後の一貫性 |
| 不確実性 | 予測区間のcoverage、誤った高confidenceの頻度 |
| 運用 | 時間、メモリ、失敗率、判定不能率 |
| 移植性 | renderer・倍率・背景による変動 |

円弧率を出すなら、単なるプリミティブ個数ではなく、**可視境界長に占める割合**等を定義する。短い円弧を大量に追加して値を水増しできる指標は避ける。

画像全体の平均差だけだと、大きな一様背景が細部の誤差を隠す。境界帯域・細線・文字の穴等も独立に測る。

### 18.5 比較条件

古典方式としてPotrace、カラー領域処理の実装としてVTracer、微分可能描画・階層的vectorizationとしてdiffvg／LIVE、適応的構造の方式としてAdaVec等を比較対象にする。[S06][S27][S05][S07][S08]

比較は、同一入力・同一出力条件で行う。

- strict SVGか、画像埋め込み可か。
- 固定時間か、固定ノード数か、固定誤差か。
- GPU利用の有無。
- 生成元情報を使ってよいか。
- 文字・グラデーション・透明度をどう扱うか。

条件が違う結果を一つの順位表にまとめない。

### 18.6 必須ablation

次の差分を測る。

```text
円フィットのみ
    vs 複数プリミティブ

通常輪郭
    vs subpixel輪郭

点群fit
    vs 画素空間refinement

独立fit
    vs 妥当性検査付き共有パラメータ

固定観測モデル
    vs 制限された観測モデル選択

共通の近似描画器だけ
    vs 独立した参照・出力検証

sampled error
    vs 連続上界

固定ノード数
    vs 適応的な構造変更
```

複雑な方式を追加したら、どの入力で効き、どの入力で悪化するかを記録する。

### 18.7 品質プリセットは達成値と混同しない

例えば0.5px、0.1px、0.025px等を**要求値**として設定することはできる。しかし、これらは本書で実画像に対して達成した値ではない。

入力が不鮮明でも、推定輪郭へ極めて小さくfitすること自体は可能な場合がある。それを元形状の高精度復元と呼ばない。

### 18.8 写真を扱う場合

写真では、境界だけでなく連続的な陰影・テクスチャも情報の大半を占める。円弧主体のモデルだけでは効率が悪い場合がある。

対応するなら、塗りとグラデーションのモデルを強化し、shape fidelityとappearance fidelityを分ける。新しい研究用画像表現を採用するときも、標準SVGとの交換可能性・編集性を確認する。

本製品の第一ターゲットは、ロゴ・アイコン・図版・フラットイラスト・線画とする。写真については別の品質・複雑度プロファイルを設ける。

## 19. 本レビューで実行した限定検算

本章だけは、設計提案ではなく本レビュー中に実行した計算結果である。ただし、**CFV-X全体の実装、実画像ベンチマーク、商用品質の達成確認ではない。**

再現用スクリプトは`review_checks.py`、結果は`review_checks_results.json`に保存した。単一Markdownでも主要な式・条件・結果は理解できるように記載する。

### 19.1 同じ画素値から異なるエッジ位置が成立する

条件：

$$
q(t)=\operatorname{round}(255(1-t))
$$

| エッジ位置t | 8bit観測 |
|---:|---:|
| 0.2501 | 191 |
| 0.2502 | 191 |

同じ観測に複数の位置が対応する。したがって、量子化後の値だけから元の位置を無条件に一意復元することはできない。

### 19.2 潜在角度の自由最適化は幾何フィットと同じ

100個の合成点について、

$$
\min_{\phi_i}\|p_i-c-r u(\phi_i)\|^2
$$

と

$$
(\|p_i-c\|-r)^2
$$

を比較した。

最大絶対差は約 **$9.99\times10^{-16}$** だった。これは倍精度の丸め程度であり、自由角度を加えるだけでは追加の情報を使っていないことを確認する計算である。

### 19.3 短い円弧では半径の情報が弱くなる

121点、独立した法線方向ノイズの標準偏差0.02pxを仮定し、

$$
J_i=(-\cos\phi_i,-\sin\phi_i,-1)
$$

$$
\operatorname{Cov}\approx \sigma^2(J^\top J)^{-1}
$$

から局所線形化した半径の標準偏差を計算した。

| 円弧の角度 | Jの条件数 | 半径の局所標準偏差近似 |
|---:|---:|---:|
| 360° | 1.414 | 0.001818px |
| 180° | 4.577 | 0.004105px |
| 60° | 46.930 | 0.042638px |
| 15° | 768.964 | 0.699057px |
| 5° | 6,930.864 | 6.300785px |

これは理想化した局所情報量の計算であり、実画像の測定誤差や非線形推定の実績ではない。特に不確実性が大きい領域では、局所Gaussian近似自体にも注意が必要である。

それでも、**同じ点数・同じ測定ノイズでも、短い円弧では半径を決める情報が大きく減る**ことが分かる。

### 19.4 補間して点数を増やしても独立情報は増えない

独立な二つの観測を、線形補間で三つにした。

$$
M=
\begin{pmatrix}
1&0\\
1/2&1/2\\
0&1
\end{pmatrix}
$$

観測共分散は $MM^\top$ となり、rankは2のままである。

| 評価方法 | 情報量 |
|---|---:|
| 元の二つの独立観測 | 2 |
| 補間後の三つを独立と誤認 | 3 |
| 相関を考慮した評価 | 約2 |

multi-scaleや超解像を、測定データが増えたことと混同してはいけない。

### 19.5 最小二乗候補の失敗は、可行解不存在の証明ではない

水平線 $y=b$ を、観測値 $0,0,0,4$ に当てる。

| fit | b | 最大誤差 |
|---|---:|---:|
| 最小二乗 | 1 | 3 |
| minimax | 2 | 2 |

要求誤差が2なら、最小二乗候補は失敗するが、可行な水平線は存在する。

円候補の枝刈りでも同じ論理的な注意が必要である。安いfitの失敗を、そのモデル族全体の不可行性に置き換えない。

### 19.6 共有境界とalphaの反例

それぞれ50%の被覆率を独立にsource-overすると、alphaは0.75になる。一方、二つの領域が画素内を相補的に埋めているなら総被覆率は1である。

これは式の検算であり、特定のブラウザで測定した結果ではない。共有境界だけでは描画アーティファクトの保証にならない理由を示す。

### 19.7 端点サンプリングだけでは内部の誤差を見落とす

$$
\gamma(t)=(t,0.2\sin^2(\pi t)),\quad t\in[0,1]
$$

を直線 $y=0$ と比較する。

端点 $t=0,1$ だけのサンプル誤差は0だが、連続的な最大距離は $t=0.5$ で0.2になる。

サンプル点での最大値を、連続曲線の最大誤差と同一視してはいけない。

### 19.8 短い円弧を直線にできる条件

半径100pxに対してsagittaを計算した。

| 円弧の角度 | 弧と弦の最大距離 |
|---:|---:|
| 5° | 0.095178px |
| 10° | 0.380530px |

同じ半径で要求誤差0.1pxなら、前者はこの幾何条件を満たし、後者は満たさない。角度だけでなく半径と要求精度も見る必要がある。

### 19.9 合成円での点群fitと画素fit

#### 条件

- 画像サイズ：32×32。
- 真の円：中心 $(15.23,15.67)$、半径8.3。
- 単色・不透明な円。
- pixel boxに対する被覆率を適応的一次元数値積分で計算。
- 積分の指定許容値：絶対・相対とも $10^{-10}$。
- 8bitへ量子化。
- 追加ノイズ・ぼけなし。
- 点群fit：0.5等値線を抽出し、幾何最小二乗。
- 画素fit：点群fitから初期化し、同じ被覆率モデルで画素最小二乗。

#### 結果

| 方法 | 推定cx | 推定cy | 推定r |
|---|---:|---:|---:|
| 真値 | 15.230000000 | 15.670000000 | 8.300000000 |
| 等値線→幾何fit | 15.227721119 | 15.680645235 | 8.295457639 |
| 被覆率→画素fit | 15.230191278 | 15.670019388 | 8.299993828 |

| 方法 | 中心の距離誤差 | 半径の絶対誤差 |
|---|---:|---:|
| 等値線→幾何fit | 0.01088643px | 0.00454236px |
| 被覆率→画素fit | 0.00019226px | 0.00000617px |

この例では、等値線へのfitより、画素ができる過程に直接合わせる方が真値に近かった。

#### この結果から言えないこと

この試験は、生成側と復元側が同じforward modelを用いた**単一の合成例**である。実画像、未知renderer、blur、透明度、多数の図形に対する性能は測っていない。

また、画素fitは量子化区間の厳密な尤度ではなく、復号した画素値への最小二乗である。非常に小さい半径誤差を、一般的な保証値や有効桁数と解釈しない。

数値積分も、厳密な外向き丸め保証付き実装ではない。本試験の目的は、**逆ラスタライズへ進む価値があるかという機構の確認**である。

## 20. 開発順序と商用化の判定基準

### 20.1 Phase 0：検証器を先に作る

最初に必要なのは、見栄えのよいデモより**正解と比較できる試験系**である。

実装するもの：

```text
合成SVG生成
独立したラスタライズ条件
点・円・円弧・Bézierの距離検査
基本位相テスト
SVGのserialize → parseテスト
ベンチマーク記録
```

この段階で、単位、丸め、full circle、角度、透明度のバグを潰す。

### 20.2 Phase 1：単色・不透明・非交差

円、直線、円弧、Bézier fallbackに絞る。

円だけに限定せず、失敗時に精度を維持する経路を初期から持つ。circle-onlyなMVPでは、直線・角・一般曲線での不必要な分割が後の設計負債になる。

合格条件は、指定範囲の合成データに対する誤差、非退化、閉路、書き出し後の一致である。達成した範囲を明示して拡張する。

### 20.3 Phase 2：有限円弧の高精度化

正規化、複数初期値、minimaxまたは制約付きfit、短い円弧の曲率表現、区間候補DPを導入する。

重点は、「fitできた」ことより、**何をfitしたかが正しく、可否判定が壊れていないこと**である。

### 20.4 Phase 3：領域とstroke

共有境界、穴、包含、線端、join、複数色に対応する。

ここで幾何の隙間と描画の継ぎ目を別々に検査する。透明度は不透明の場合と同じルールで扱わない。

### 20.5 Phase 4：画素空間の精密化

単純な被覆率モデルから始め、効果のある範囲だけ観測モデルを追加する。

最適化用の描画器と独立した検証器を分離する。学習器やGPU化より先に、小規模で再現可能な改善を確認する。

### 20.6 Phase 5：幾何関係とレイヤー

同心・同半径・接線・対称性を、採否判定付きで導入する。

隠れた構造の補完や意味的なレイヤー復元は、観測された境界と混ぜない。必要に応じてユーザー承認を設ける。

### 20.7 Phase 6：製品品質

商用公開の判定には、以下が必要である。

| 項目 | 判定内容 |
|---|---|
| 忠実度 | 対象範囲の評価データで要求値を満たす |
| 幾何保証 | 保証対象・数値方式・判定不能を明示 |
| 位相 | 細線・穴・近接境界で破損を検出 |
| 互換性 | 最終SVGを対象環境で検証 |
| 再現性 | 入力・設定・版・seed・結果を追跡 |
| 安全性 | 巨大画像・異常データ・外部参照・時間超過を管理 |
| 操作性 | 原画像比較、誤差可視化、低信頼箇所の修正 |
| データ管理 | ローカル／サーバー処理、保持・削除の方針を明示 |
| 依存関係 | コード・モデル・データの版と利用条件を記録 |
| 失敗処理 | 黙って品質を下げず、理由と状態を返す |

本書ではライブラリやモデルの商用利用条件を確定していない。採用する版のライセンス、依存関係、学習済み重み、評価データ等を実装時に確認する。自前実装であれば他の権利・条件を一切確認しなくてよい、とは扱わない。

### 20.8 ユーザーが修正できるインターフェース

自動推定だけに閉じない。

```text
この部分は円である
この二つは同じ半径
ここは角を残す
この線は接続しない
この領域は別レイヤー
この隠れた部分は推定しない
```

という制約を入力できるようにする。

少量の正しいユーザー制約は、観測だけでは決まらない問題を解消できる。ただし、画像と矛盾する制約が与えられたら、その矛盾も報告する。

## 22. 最終仕様としての要約

### 22.1 採用する中心原則

> **画像に忠実な候補を先に確保し、その忠実度を維持したまま、幾何構造・編集性・移植性を改善する。**

中心となる機構は、

$$
\boxed{
\text{複数幾何仮説}
+
\text{観測モデル}
+
\text{逆ラスタライズ}
+
\text{制約付き共同最適化}
+
\text{独立検証}
}
$$

である。

### 22.2 円フィッティングの最終的な役割

円フィッティングは、画像をすべて円へ変換する処理ではない。

**画像の一部を円という低自由度で意味のある構造が説明できるか、確認するための推定器**である。

それが確認できれば、円として保存する。確認できなければ、楕円・直線・Bézier・別の領域表現へ移る。この判断も含めて高精度化である。

### 22.3 商用品質の定義

商用品質とは、平均的にきれいなSVGを出すことだけではない。

**入力条件に応じて処理を選び、どこまで忠実で、どこから推定で、どの条件なら再利用できるかを説明できること**である。

そのため出力は、

```text
SVG
+
共有パラメータを含む編集用構造
+
誤差・位相・renderer互換性のレポート
+
不確実性と推定部分の情報
```

とする。

### 22.4 最終到達点

最終目標は「元SVGを必ず当てる機械」ではない。

> **観測画像が許す範囲で、最も忠実で、最も説明可能で、最も扱いやすいベクトル表現を選び、その品質を検証できるシステム。**

この定義なら、元の「円フィッティングを中心に高精度SVGへ分解する」という発想を保ちながら、実装可能性・理論の整合性・製品としての信頼性を一つにまとめられる。

### 23.3 付属する検算資料

- `review_checks.py`：本レビューの小規模検算。汎用vectorizerではない。

- 本Markdown：理論・設計・修正点・主要結果をまとめた単体文書。

検算結果の機械可読JSONと本書の表が食い違う場合は、条件を確認したうえで再実行し、原因を調べること。試験を増やしても、検証していない入力範囲まで達成精度を拡張して主張しない。
